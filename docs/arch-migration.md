# Разворот архитектуры: gateway (РФ) берёт на себя модель, маскирование и ML

> Статус: ПЛАН (согласован 2026-06-27). Код ещё не начат — фаза 1 стартует по «погнали».
> Контекст и текущая архитектура — в `CLAUDE.md` и `DEPLOY.md`.

## Зачем

Граница между двумя репозиториями переносится **на момент нажатия «отправить вопрос модели»**:

- **paragraf-monorepo** — всё «до отправки»: сайт, кабинет, окно чата, сценарии, БД, бэкенд
  (`web`, `engine` (тонкий), `billing`, `doc-tools`, `landing`).
- **paragraf-gateway (РФ)** — всё «после отправки»: маскирование, выбор модели, вызов модели,
  обработка/трансформация ответа, демаскирование и **ML-часть** (валидация/перепроверка ответов).
  Здесь же работает ML-коллега.

**Инвариант 152-ФЗ:** сырые ПДн не покидают РФ. gateway РФ-серверный; за границу уходит
**только** исходящий HTTPS к зарубежной модели (Claude) с уже обезличенным текстом.

## Принятые решения

1. **Язык gateway-app — TypeScript (Bun/Hono).** Переиспользуем готовый TS-код (PII-маскер +
   тесты, auto-model, оркестрация chat.ts). LiteLLM остаётся Python-контейнером за app-слоем.
   ML-шаг коллеги — по внутреннему HTTP (язык-агностично).
2. **ПДн хранятся сырыми в engine DB (РФ), vault эфемерный.** Браузер шлёт сырой текст, engine
   хранит сырой. gateway маскирует пер-реквест (mask → модель → демаск ответа → vault
   выбрасывается). Постоянного vault нет нигде; браузерный localStorage-vault и демаск-на-рендере
   удаляются. Требование к деплою: **шифрование БД at-rest** (engine/billing Postgres).
3. **ML-шаг работает по обезличенному тексту** (после модели, до демаскирования). Контракт — ниже.

## Целевой поток

```
Браузер (web)            engine (РФ, тонкий)             gateway (РФ, app-слой)
  компонует вопрос  ──▶  POST /session/:id/prompt   ──▶  POST /answer { сырой текст }
  (UI/сценарии)          хранит user-msg (сырой)            │ OCR (если картинка)
                         гейтит кредиты                     │ маскирование
                                                            │ выбор модели (auto)
                                                            │ вызов модели ──(обезличенный)──▶ Claude (зарубеж)
                                                            │ ML-валидация ответа (обезличенный)
                                                            │ демаскирование
  ответ по SSE      ◀──  релеит стрим               ◀──    стрим { дельты + meta }
                         хранит assistant-msg (сырой)
```

## Контракт engine ↔ gateway

Заменяет нынешний `engine → LiteLLM /v1/chat/completions (маскированный)`.

```
POST gateway:/answer
{
  sessionID, userKey,                 // userKey = virtual-key LiteLLM (бюджет/модели)
  model: "auto" | "claude-sonnet" | "gigachat-pro" | ...,
  deepThinking: boolean,
  messages: [ { role, content } ],    // СЫРОЙ текст (РФ→РФ)
  attachments?: [ { mime, data } ]    // картинки → OCR на сервере
}
→ стрим (SSE):
  event delta   { text }              // демаскированные дельты
  event meta    { modelUsed, masked: {count}, ml: {verdict, flags}, usage: {tokensIn,tokensOut} }
  event done    {}
```

engine: хранит сообщения (сырые), релеит стрим в браузерный SSE, гейтит кредиты до вызова,
отдаёт usage в ETL-путь.

## Контракт ML-шага (внутри gateway)

Срабатывает после ответа модели, до демаскирования — на **обезличенном** тексте.

```
POST (внутренний) /ml/validate
{
  requestId, sessionId, vertical: "lawyer"|"accountant",
  model, question: "<обезличенный>", answer: "<обезличенный>",
  context?: ["<обезличенная история>"], usage: { tokensIn, tokensOut }
}
→
{
  verdict: "ok" | "revise" | "reject",
  confidence: 0..1,
  answer?: "<исправленный обезличенный>",         // при revise
  flags?: [ { type, note } ],
  meta?: { model, latencyMs, cost }
}
```

Стриминг по умолчанию: ответ модели идёт живьём, ML валидирует пост-фактум и при `revise`
досылает правку. Высокорисковый режим (буфер→валидация→отдача) — конфигом.

## Фазы (каждая отдельно проверяема и обратима)

| # | Фаза | Что | Где | Проверка |
|---|---|---|---|---|
| 1 | Контракт + каркас | новый Bun/Hono app в gateway; `/answer` пока passthrough в LiteLLM; engine переключается с `/v1/chat` на `/answer` | gateway (новый app), engine | e2e чат зелёный |
| 2 | Маскирование → gateway | перенос `ourapp/pii` (masker+тесты) в gateway; пер-реквест mask/демаск; **удаление PII-слоя из браузера** (vault, global-unmask) | gateway, web | PII-тесты в gateway; чат маскирует на сервере перед egress |
| 3 | Оркестрация → gateway | перенос `engine/chat.ts` (вызов/стрим/заголовки/deep-thinking) + `auto-model/classify`; engine худеет до store+forward+credits | gateway, engine, web | стрим/заголовки/авто-модель работают |
| 4 | OCR → gateway | Tesseract server-side; браузер шлёт картинку в gateway; убрать web tesseract-ассеты + MIME-плагин | gateway, web | скан-договор распознаётся |
| 5 | ML-валидация | каркас `/ml/validate` + заглушка; контракт для коллеги | gateway | заглушка проходит, коллега наполняет |

## Риски / меры

- **Egress к Claude из РФ.** gateway РФ → Anthropic нужен зарубежный выход (egress-узел/прокси —
  бывший зарубежный кусок). Единственное, что пересекает границу, с маскированным текстом.
  GigaChat/Yandex — РФ, выход не нужен.
- **ПДн в БД (РФ).** engine DB теперь хранит сырые ПДн → шифрование at-rest, ограничение доступа.
- **Кредиты/ETL почти не меняются.** LiteLLM остаётся внутри gateway → spend-логи и провижн
  ключей billing→gateway работают как есть (теперь РФ→РФ).
- **UX-паритет.** Браузер худеет (минус крипто-vault, минус Tesseract); контролы («Углублённо»,
  «Авто», индикация маскирования) остаются — на сервер уходит только их логика.

## Что НЕ меняется

billing, doc-tools, landing, UI/сценарии/кабинет (меняются только внутренности
PII/OCR/авто-модель/deep-thinking — уходят на сервер), инвариант 152-ФЗ.
