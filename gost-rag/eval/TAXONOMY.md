# Таксономия задач инженера-технолога (для eval-широты)

Текущий gold (`data.md` → `gold.yaml`) покрывает ОДИН тип — «подбор: какие стандарты + классы». Реальный
ассистент шире. Ниже — типы вопросов, по которым генерируем синтетический gold (`gold_synth.yaml`) и под
которые расширяем разметку. Поле `task_type` в gold кодирует тип; метрики харнесса считаем ПО ТИПАМ.

| task_type | что спрашивают | пример | что значит «правильно» |
|---|---|---|---|
| **selection** | подбор материала/изделия под условия | «Арматура для фундамента, -40..+50, неагрессивная — что взять?» | названы применимые классы/изделия + ссылки на нужные стандарты/пункты |
| **lookup** | конкретное требование/значение из пункта | «Какой диапазон температур у climatic-исполнения УХЛ1?» | точное значение + дословная цитата пункта-источника |
| **substitution** | допустимость замены/аналога | «Можно ли А500С вместо А400 в этом узле?» | да/нет/условно + пункт, обосновывающий ограничение |
| **norm_conflict** | иерархия/конфликт норм | «ГОСТ и СП дают разное — что главнее?» | какой документ приоритетен и почему (область применения/статус) |
| **procedure** | метод/процедура (испытание, сварка, контроль) | «Как испытать арматуру при нагреве?» | метод + ссылка на стандарт метода |
| **interpretation** | толкование формулировки пункта | «Что значит „в части воздействия климатических факторов“?» | разъяснение строго по тексту пункта |
| **multihop** | синтез из нескольких документов | «Композитная арматура на улице в коррозии — что и где смотреть?» | все нужные документы покрыты + увязка |
| **negative** | ответа НЕТ в корпусе → воздержание | «Ставка НДС на арматуру?» | система воздерживается (abstain) |

## Принципы генерации (защита валидности)
- Вопрос — **реалистичная инженерная формулировка** (сценарий: «у меня X в условиях Y, …»), НЕ копия фразы из
  стандарта (иначе ретрив тривиален → метрика завышена).
- Ответ и цитата — **строго заземлены** в реальных пунктах документа (verifier сверяет с текстом пункта).
- Кросс-вендорная **верификация** (генератор и проверяющий — разные модели); отклонять при сомнении.
- Каждая запись помечена `source: synthetic` (vs `human` для `data.md`), есть `split: train|test` (held-out).
- Синтетика — для **широты и регрессии** (config A vs B по типам), не абсолютная истина; человеческий gold —
  якорь доверия. Финальный сэмпл — ручной просмотр.
